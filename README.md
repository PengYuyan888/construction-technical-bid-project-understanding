# construction-technical-bid-project-understanding

这是一个用于编制建筑工程技术标“项目认识／工程概况”类章节的 Codex Skill。它会从当前项目的招标文件、澄清答疑、工程量清单、施工图、勘察资料、现场资料和 Word 模板中核实事实，形成项目定位、建设意义、工程概况、专业设计概况、项目特点、施工现场现状及周边环境等内容。

Skill 主要面向新建项目，同时兼容改扩建、修缮和城市更新项目。章节名称不必固定为“对项目拟建工程现状的了解与认识”，只要任务实质属于项目认识、总体概述或工程概况即可使用。

## 主要能力

- 盘点并区分招标文件、施工图、清单、勘察资料、格式模板和参考标书；
- 建立内部事实台账，记录项目名称、范围、规模、参数、材料和做法的来源；
- 识别文件版本、专业口径和数据冲突，不擅自取值或补齐缺失数据；
- 根据项目类型选择新建或改造分支，按建筑、结构、机电、室外和专项工程展开；
- 使用表格和工程行业语言编写内容，减少空泛套话、含糊引用和不完整句子；
- 有模板时严格沿用，无模板时先征得用户授权；
- 需要模型作图时先提交一张代表性样图，确认后再批量制作；
- 先提交编写或修改计划，只有用户明确确认后才生成或修改 Word；
- 对 Word 成品进行渲染、表格换行、批注、修订痕迹和局部修改差异检查。

## 适用场景

### 新建工程

- 住宅及配套、人才房、保障房；
- 办公楼、商业综合体和公共建筑；
- 学校、医院、文化体育场馆；
- 工业厂房、仓储物流和产业园；
- 高层、超高层、地下室及深基坑工程。

### 改扩建和修缮工程

- 既有建筑改扩建、功能调整和结构加固；
- 老旧小区、公共建筑和工业设施修缮；
- 屋面、外墙、公共部位和附属设施改造；
- 既有机电系统、室外管网、道路和园林改造。

### 典型任务表达

- “根据招标文件和全套图纸编写技术标第一章项目总体认识。”
- “把住宅项目的工程概况按建筑、结构、机电和室外工程展开。”
- “参考我提供的技术标写法，按现有 Word 模板编制项目概况。”
- “修改现状认识章节，保持表格和版式不变，只调整指定内容。”

## 不适用的任务

以下任务不应仅使用本 Skill：

- 单独编制施工组织设计、专项施工方案或应急预案；
- 编制商务标、投标报价、成本测算或合同索赔文件；
- 只读取、OCR 或摘要某一份 PDF／设计说明；
- 只进行 Word 排版、图片编辑或图纸深化，不编写项目认识类内容；
- 在缺少项目资料时要求凭经验生成具体工程参数。

## 运行条件

- 已安装 Codex，并允许读取当前项目文件；
- 使用 npm 安装时需要 Node.js 16.7 或更高版本；
- 生成或修改 Word 时，需要当前运行环境具备 DOCX 创建和渲染能力；
- PDF、扫描图、DWG 等文件能否直接识读，取决于当前模型和可用工具。能力不足时，Skill 会说明限制并采用 OCR、转换、截图或占位符等可行方式。

## 更新、备份和卸载

通过 npm 更新时使用：

```powershell
npx -y construction-technical-bid-project-understanding@latest -- --force
```

`--force` 不会直接删除旧版本。安装器会先在同一目录完成临时安装和完整性检查，再把旧 Skill 改名为带时间戳的备份目录，最后启用新版本。安装失败时会恢复旧目录。

确认新版本可用后，可自行删除不再需要的 `.backup-时间戳` 备份目录。卸载时删除 `skills` 目录下的 `construction-technical-bid-project-understanding` 文件夹即可。

通过 GitHub 克隆安装的版本，可在 Skill 目录中执行 `git pull` 更新；更新前仍建议保留一份副本。

## 使用前准备

资料越完整，结果越可靠。建议把下列文件放在清晰命名的项目目录中：

1. 招标公告、招标文件、合同条件、补充通知和答疑；
2. 工程量清单、招标范围和专业责任划分；
3. 建筑、结构、给排水、消防、电气、暖通、园林、道路和基坑等施工图；
4. 岩土勘察、测绘、既有管线、现场照片和踏勘资料；
5. Word 模板、章节大纲、格式要求、表格示例和图片示例；
6. 参考技术标。参考标书只用于学习结构、深度和表达方式，不作为当前项目事实来源。

## 具体工作流程

### 1. 开始确认

Skill 首先确认是否需要图片、图片采用模型制作／图纸提取／占位符中的哪种方式，以及是否有必须沿用的 Word 模板。没有模板时，只有用户明确授权才会使用内置备用模板。

### 2. 资料盘点

检查文件能否读取，区分招标资料、设计资料、现场资料、格式模板和参考标书，并确认各文件版本和适用范围。

### 3. 事实核查

为项目名称、地点、建设单位、规模、范围、工期、质量目标、材料、构造和系统参数建立内部事实台账。数据冲突时列明双方来源和影响，不自行选择。

### 4. 项目类型和章节映射

判断项目属于新建、改扩建、修缮还是混合工程，再把用户现有章节名称映射到项目定位、建设意义、工程概况、设计概况、特点和现状等功能模块。标题是否调整，以用户模板、大纲和授权为准。

### 5. 提交计划

在生成或修改 Word 前，先提交具体的编写／修改计划，包括资料范围、章节安排、表格和图片设置、事实冲突、格式处理及交付文件名。

### 6. 等待用户确认

用户没有明确确认计划时，不生成或修改 Word。此阶段仍可继续进行只读核查和问题汇总。

### 7. 编写和排版

确认后按事实台账编写内容，项目概况优先采用表格，项目定位、建设意义和特点采用适量文字。表格句子保持完整，具体做法写清部位、对象、材料、动作和参数含义。

### 8. Word 核验

渲染全部页面，检查标题层级、表格跨页、图片清晰度、空白页、批注和修订痕迹。表格内的多个列点使用独立 Word 段落，不使用 Shift+Enter 手动换行或可见的 `^p` 字符。

### 9. 修改和交付

后续修改仍先提交修改计划。用户要求“其他内容不动”时，只修改指定段落、单元格或图片对象，并比较修改前后的 Word 包部件。默认只交付用户要求的 Word 成品。

## 事实和资料使用范围

- 项目名称、范围、规模、工期和目标以当前项目有效招标资料为准；
- 建筑、结构和机电做法以相应专业有效施工图为准；
- 地质、水文、周边建构筑物和地下管线以勘察、测绘和现场资料为准；
- 工程量清单可用于判断单位工程构成和数量，但不能代替施工图完整做法；
- 通用规范参数不能写成本项目设计参数；
- 参考标书的项目名称、地点、规模、参数、做法和承诺不得写入当前项目；
- 资料缺失时不凭经验补齐关键数据；资料冲突时等待用户裁定。

## Word、表格和图片规则

- 有用户模板时严格沿用页面、样式、标题、表格、页眉页脚和题注；
- 没有模板时先询问，用户授权后才能使用内置模板；
- 表格内容可详细，但句子必须完整，不能省略部位、对象或参数用途；
- 不使用“按图施工”“详相应大样”等无法独立阅读的含糊表达；
- 是否增加、删除或调整标题，以用户授权为准；未获得授权时保留现有结构；
- 模型制作图片时先提交一张样图；无法识图或作图时如实说明并使用占位符；
- 多代理可用于并行读取大量资料，但只能由一名汇总者统一事实，由一名编辑者处理最终 Word。

## 使用边界

本 Skill 负责把项目资料转换成技术标项目认识类内容，不代替设计复核、图纸会审、现场探测、工程量核算和执业人员审签。输出内容仍应由投标编制人员结合最新招标补遗、现场情况及企业承诺进行最终审核。

Skill 不会因为用户要求“内容丰富”而虚构面积、栋数、户数、工期、结构参数、绿色等级、奖项目标或示范地位。项目定位和建设意义可以在事实基础上提升表达，但不能创造新的客观事实。
