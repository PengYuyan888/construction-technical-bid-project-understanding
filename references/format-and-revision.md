# 格式、图片与修改规则

## 模板优先级

1. 用户提供的 Word 模板、格式规范、表格示例和图片示例具有最高优先级。
2. 有模板时复制并沿用已有页面设置、样式、标题编号、表格格式、页眉页脚和题注，不自行“美化”或重设计。
3. 没有模板时必须询问；只有用户明确授权，才可复制 `assets/default-template.docx` 作为起点。
4. 不直接改模板原件或用户原稿，另存新文件。

## 标题和分页

- 严格遵守用户给定的一至四级标题权限。
- 标题文字和编号是否自动生成，以模板现状为准。
- 不擅自插入分页符、分节符或改变纸张方向；确有必要时先列入计划。
- 表格标题和图片标题只写用户要求的名称；编号、样式和位置按模板处理。

## 表格

- 复制用户示例表格的样式、边框、行高、列宽、段落和字体。不得因内容增加而重建一套近似样式。
- 用户规定首行、首列、内容单元格或序号列宽时，精确执行。
- 表格不使用填充色，除非模板明确存在；不得自行加入深色或黑色底纹。
- 单元格分点使用多个 `w:p` 段落。禁止用 `w:br`、Shift+Enter 或手动换行代替段落，也禁止把 Word 查找替换代码 `^p` 作为可见文字插入。
- 句子写完整，说明部位、对象、动作、材料或参数含义；允许单元格文字较长。

## 图片

开始时就确认是否需要图片，并按一种方式执行：

1. **模型制作**：先做一张代表性样图，用户确认构图、颜色和专业程度后再批量制作。
2. **图纸提取**：从有效图纸截取或导出，保留可识别的比例、图名或必要信息，核对分辨率和裁切范围。
3. **占位符**：写清图片标题和拟插入内容，保留适当空间，由用户后续替换。

图片内部原则上不放说明文字；确需说明时写在正文或图片标题附近。可使用浅色填充，避免深色和黑色大面积填充。

## Word 生成与检查

- 使用文档工具要求的 DOCX 创建、渲染和逐页检查流程。
- 检查字体、标题层级、表格宽度、跨页断行、空白页、孤行、图片清晰度、题注位置和正文溢出。
- 执行 `scripts/audit_docx.py` 检查手动换行、分页符、修订痕迹和批注。
- 成品不能依赖未交付的外链图片、临时文件或本机绝对路径。

## 修改稿

1. 先读取用户最新稿及修改意见，提交逐项修改计划，确认后再动手。
2. “其他内容一律不动”表示只修改指定 XML 段落、表格单元格或图片对象；不得全篇重排、重建表格或重新应用样式。
3. 使用 `scripts/compare_docx_parts.py` 比较原稿和修改稿；确认非必要部件没有变化。
4. 需要反馈处理情况时，逐条说明“修改位置—修改内容—核验结果”，不得只写“已修改”。

## 交付

默认只交付用户要求的 Word 文件。内部事实台账、文本抽取、截图、渲染页、差异报告和检查日志不随成品交付，除非用户明确要求。
